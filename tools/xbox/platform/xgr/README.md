# xgr: xgameruntime stand-in

`idl_table.py` + `gen_stub.py` build a typed interface table from IDL files and generate `xgameruntime.dll` source from it (not committed: the IDLs are LGPL, from the Xodus project).
Two builds, from an x64 VS prompt in this directory:

```
python -I idl_table.py <xodus>/include table.json
python -I gen_stub.py table.json gen
:: logging stub only (every method logs its first call and fails)
cl /nologo /LD /O2 /EHsc /std:c++17 gen\xgr_stub.cpp /Fe:xgameruntime.dll /link /DEF:gen\xgameruntime.def
:: with the runtime: XTaskQueue/XAsync and system info (vendored from GrandTheftXbox, MIT, runtime\GTX_LICENSE.txt) plus an offline local user (runtime\impl_user.cpp)
cl /nologo /LD /O2 /EHsc /std:c++20 /DXGR_WITH_RUNTIME /I runtime gen\xgr_stub.cpp runtime\xtask.cpp runtime\impl.cpp runtime\impl_user.cpp runtime\impl_storage.cpp runtime\impl_package.cpp runtime\impl_save.cpp runtime\impl_system.cpp runtime\gtx\gtx_log.cpp /Fe:xgameruntime.dll /link /DEF:gen\xgameruntime.def
cl /nologo /EHsc test_client.cpp
cl /nologo /EHsc /std:c++20 test_package.cpp
cl /nologo /EHsc /std:c++20 test_save.cpp
cl /nologo /EHsc /std:c++20 test_system.cpp
```

Environment: `XGR_LOG=<file>` (interfaces queried, first call of each stubbed method, unknown interface ids), `GTX_LOG=<file>` (the vendored layer), `XGR_GAMERTAG`, `XGR_USER_ID`, `XGR_PLS_DIR` (persistent local storage directory; default `PersistentLocalStorage` next to the executable), `XGR_PLS_SIZE_MB` (its quota; default the `SizeMB` of `MicrosoftGame.Config` next to the executable), `XGR_PACKAGE_ID`, `XGR_PACKAGE_STORE_ID`, `XGR_PACKAGE_DISPLAY_NAME`, `XGR_PACKAGE_PUBLISHER`, `XGR_PACKAGE_DESCRIPTION`, `XGR_PACKAGE_VERSION`, `XGR_TITLE_ID` (package identity when `MicrosoftGame.config` does not give it; otherwise synthetic), `XGR_PACKAGE_ID`, `XGR_PACKAGE_STORE_ID`, `XGR_PACKAGE_DISPLAY_NAME`, `XGR_PACKAGE_PUBLISHER`, `XGR_PACKAGE_DESCRIPTION`, `XGR_PACKAGE_VERSION`, `XGR_TITLE_ID` (package identity when `MicrosoftGame.config` does not give it; otherwise synthetic), `XGR_SAVE_ROOT` (game saves; default `%LOCALAPPDATA%\xgr\saves`, then `<user id>\<service configuration id>`), `XGR_LOCALE` (the locale `XPackageGetUserLocale` reports; default the first preferred Windows UI language the title's `MicrosoftGame.Config` lists).
`test_client.cpp` reaches the DLL the way the GDK's static library does (`QueryApiImpl` + vtable slots): it adds the local user through the async framework, reads id, state and a privilege,
and the system analytics info (reports Windows.Xbox / Xbox Series X). Implemented: the whole XAsync/XTaskQueue layer, XThread hints, system and title ids, and the user functions with no network (XUserAdd*, ids, gamertag, state, age group, privileges, change-event registration, sign-out deferral (E_GAMEUSER_DEFERRAL_NOT_AVAILABLE outside a sign-out), device association, the desktop answers for the default audio endpoint and controller lookup), and persistent local storage (path, path size, space info: a directory limited to the title's declared quota), and XPackage for a title that is one fully installed package in the executable's directory (identity, enumeration, chunk and feature queries, install monitors, mounting the main package, write statistics; `test_package.cpp` checks it). Anything needing a store or a download returns the documented error. Every XGameSave and XGameSaveFiles function is local-only storage (`runtime\impl_save.cpp`): each container is a folder of blob files plus a manifest replaced in one rename, so a failed or abandoned update keeps the previous contents; titles' container and blob names never become file names. Nothing syncs (`needsSync` is always false), the quota is the documented 256 MB per user and configuration id, and `XGameSaveFilesGetFolderWithUi` shows no UI. `test_save.cpp` checks them; run it, then `test_save.exe reopen` to check that saves survive a new process.
Everything else logs and fails: package store (downloads, DLC), store, game UI that needs a window, network queries, closed captions, speech, launching, gamer picture, tokens.
`runtime/impl_system.cpp` (tested by `test_system.cpp`) adds the startup-facing system calls with honest offline answers: app-specific device id (the documented all-zero id), download-bandwidth hint, display timeout deferrals (a Windows display-required power request), the HDR state of the primary desktop output (read through DXGI), error callback and options,
feature availability (derived from the override table), activation/protocol/invite registrations that never fire, an offline connectivity hint (stack initialised, no connectivity, initial notification as documented), the PC answers for networking configuration and statistics, high-contrast mode from Windows, and the headless game UI (dialogs, pickers and text entry complete with E_ABORT; no window is ever shown).

Vendored files (`runtime/xtask.*`, `xgr_internal.h`, `impl.cpp`, `gtx/`) are GrandTheftXbox's; `impl.cpp` has one local change, marked in the file.

Behaviour of the implemented methods where the console is not matched exactly (written from the interface signatures and the public GDK documentation):
* Persistent local storage (`runtime/impl_storage.cpp`): a directory, `XGR_PLS_DIR` or `PersistentLocalStorage` next to the executable, created on first use; the path ends in a backslash like the console's `T:\`.
  Quota: `XGR_PLS_SIZE_MB` or the `SizeMB` of `MicrosoftGame.Config`; a title that declares none gets `E_NOTIMPL` (the console's answer is not known).
  Space info: total = quota, used = size of the files under the directory, total free = quota - used, available = that limited by the PC volume's free space (no cluster or metadata accounting).
  `PromptUserForSpaceAsync/Result` (system UI) and `MountForPackage` log and fail.
* `XUserGetGamertag`: `XGR_GAMERTAG` or `Player`; Classic is cut to 15 bytes; the offline profile has no modern suffix, so ModernSuffix is empty and UniqueModern equals Modern.
* A buffer shorter than the text plus its terminator gets `HRESULT_FROM_WIN32(ERROR_INSUFFICIENT_BUFFER)`; the console's code for that case is not verified.
* `XPackageIsPackagedProcess` (`runtime/impl_package.cpp`): true, as for a console title. `XPackageGetUserLocale`: `XGR_LOCALE`, else the first of the user's preferred Windows UI languages that `MicrosoftGame.Config` lists under `Resources` (case-insensitive), then the first listed language with the same primary subtag, then the first listed language; with none listed, the user's default locale. The console's matching rules (script subtags, regional fallbacks) are not verified.
* Game streaming (`runtime/impl_streaming.cpp`, tested by `test_streaming.cpp`): a title that runs locally and is never streamed. `XGameStreamingInitialize`/`Uninitialize` track the init state and every HRESULT call outside it returns `E_GAMESTREAMING_NOT_INITIALIZED`. `IsStreaming` is false and no client is ever connected, so per-client queries return `E_GAMESTREAMING_CLIENT_NOT_CONNECTED`, gamepad-reading queries `E_GAMESTREAMING_NOT_STREAMING_CONTROLLER`, and the server location `E_GAMESTREAMING_NO_DATACENTER` with a name size of 0. Connection-state registrations are accepted and never fire; touch layout requests do nothing; `XGameStreamingSetResolution` accepts only 1280x720 and 1920x1080.
* `runtime/impl.cpp` (vendored) also registers `impl_storage.cpp`'s and `impl_package.cpp`'s overrides, next to `impl_user.cpp`'s.
